## 0. Проблема

Панель зливається з контентом (скрін користувача 2026-11-11): фон `bg-surface` = колір сторінки, рамка `border-surface-border` (`#2a2f3a`) сіра, тінь `shadow-nav-panel` чорна й навмисно легка. Акцент застосунку — помаранчевий (`accent`, іконки й кнопки), а панель його не несе. Потрібно: панель контрастніша й помітніша, бордер і тінь — помаранчеві, і помаранчевий акцент зверху показує, яка вкладка активна.

## 1. Панель: помаранчевий бордер і світіння

1. **Рамка:** `border-accent/70` товщиною **1.5 px** (замість `border border-surface-border`). Якщо дробова товщина дає розмиття на якомусь DPR — 1 px і `border-accent/80`, рішення в плані.
2. **Тінь — оновити токени в `frontend/tailwind.config.js`** (коментар біля токенів переписати):
   - `nav-panel`:
     `0 0 0 4px rgba(255,90,54,0.07), 0 -8px 30px rgba(255,90,54,0.28), inset 0 1px 0 rgba(255,140,110,0.14)` — тонке зовнішнє кільце, світіння вгору, теплий відблиск верхнього краю.
   - `nav-panel-open` (аркуш «Додатково» відкритий): **без світіння вгору** — лише кільце й відблиск (`0 0 0 4px rgba(255,90,54,0.07), inset 0 1px 0 rgba(255,140,110,0.14)`). Причина та сама, що й зараз: панель тоді над аркушем, і світіння тонувало б його останній рядок.
3. Фон панелі (`bg-surface`) — **без змін**; висота й відступи — без змін (зовнішнє кільце `box-shadow` не впливає на layout).
4. Перевірити, що зовнішнє кільце 4 px не обрізається краєм екрана (відступ 6 px — вміщується) і не зливається з safe area на iOS.

## 2. Рухома хвиля над активною вкладкою

Два декоративні шари всередині `nav` (`aria-hidden`, `pointer-events-none`), під табами за `z`:

**Лінія** — на верхньому краї панелі:
```css
top: -2px; left: 0; width: 110px; height: 3px; border-radius: 3px;
background: linear-gradient(90deg, rgba(255,90,54,0), #FF6A45, #FFB199, #FF6A45, rgba(255,90,54,0));
box-shadow: 0 0 8px rgba(255,90,54,.55), 0 0 18px rgba(255,90,54,.25);
transform: translateX(var(--wave-x));
transition: transform .42s cubic-bezier(.22,1,.36,1);
```

**Світіння під лінією** — м'яка пляма всередині панелі:
```css
top: 0; left: 0; width: 180px; height: 52px; border-radius: 24px;
background: radial-gradient(ellipse 50% 100% at 50% 0%, rgba(255,90,54,.22), rgba(255,90,54,0) 70%);
transform: translateX(var(--glow-x));
transition: transform .45s cubic-bezier(.22,1,.36,1);   /* на 30 мс довше — легкий шлейф */
```

- Рухати **через `transform`**, не `left` (у макеті `left` — лише для простоти канвасу): без перерахунку layout, плавно на телефоні.
- Кольори градієнта — з `accent`; якщо в `tailwind.config` немає світлішого відтінку для `#FFB199`/`#FF6A45` — додати як `accent.light`/`accent.soft` або лишити в одному місці (CSS-змінні в `index.css`), рішення в плані.
- **Яскравість — саме як у макеті.** Користувач окремо просив приглушити — не підсилювати.
- **Лише ковзання.** Без пульсації в спокої і без розтягування лінії при переході — користувач обидва ефекти прибрав.

### 2.1 Позиція
- Ціль хвилі — **той таб, чий квадрат зараз підсвічений**, тобто та сама умова, що вже дає `bg-accent` у `squareClass`. За `navigation.md`: поки аркуш відкритий або маршрут — один із пунктів «Додатково», підсвічена кнопка «Додатково» → хвиля стоїть над нею; закрили аркуш — повертається на активний таб. Окремої логіки не вводити.
- Центр рахувати **з DOM**: `center = cell.offsetLeft + cell.offsetWidth / 2` (клітинка-таб, не квадрат — вони співвісні).
- `--wave-x = clamp(center − 55, 14, navWidth − 14 − 110)`, `--glow-x = clamp(center − 90, 0, navWidth − 180)` — щоб на крайніх табах лінія не вилазила за заокруглений кут. Утиліта — чиста функція (напр. `utils/navWave.ts`) заради юніт-тесту.
- Перерахунок: при зміні підсвіченого таба і в `ResizeObserver` на `nav` (поворот, зміна safe area, ширина 360/375/390/430).

### 2.2 Анімація й доступність
- **Перший рендер / перезавантаження — без анімації:** виставити позицію до ввімкнення `transition` (клас-прапорець після першого кадру).
- `motion-reduce:transition-none` на обох шарах — хвиля перескакує миттєво (як уже зроблено для квадрата).
- `forced-colors:hidden` на обох шарах — у високому контрасті це шум; активність і так показує `Highlight`.
- Шари не мають отримувати фокус і не впливають на доступні назви табів.

## 3. Що НЕ змінюється

Розмір, положення й радіус капсули, `--bottom-nav-h` (72px), сітка й тап-зони, квадрат і його тінь `nav-active`, іконки й `--icon-bg`, кольори табів, анімації квадрата (180 ms, `scale .92`), фокус-кільце, `forced-colors` квадрата, логіка `z-50`/`z-30`, аркуш «Додатково» (вміст, анімація, закриття), i18n (нових ключів нема), `lg+`.

## 4. Перевірка

- Юніт: функція позиції — перший, середній, останній таб при ширині 363 px (телефон 375) і 418 px (430).
- `frontend`: `build`.
- Вручну (`tester`, dev-стек), 360, 375, 390 і 430 px:
  - хвиля над активним табом на кожній із 4 сторінок; перехід — плавне ковзання; перший рендер — без «приїзду» з краю;
  - аркуш «Додатково»: хвиля переїжджає на «Додатково» і назад при закритті; світіння вгору вимкнене, останній рядок аркуша не тонований;
  - маршрут із «Додатково» (Розклад / Імпорт / Інтеграції) — хвиля над «Додатково»;
  - поворот екрана / зміна ширини — хвиля на місці;
  - `prefers-reduced-motion` — миттєво; `forced-colors` — шарів нема, активний таб видно;
  - картка над панеллю читається (світіння не з'їдає низ картки — проблема з `nav-floating-rounded.md`);
  - iOS safe area (емуляція з inset): кільце й світіння не обрізаються.
  - 1440 px — без змін.
- Порівняти зі скріном артборда E на канвасі.
