# 02 · Тупикові стани: 404, неіснуюче тренування, офлайн

Гілка: `fix/dead-end-states`. Знахідка рев'ю F06. Лише фронтенд.
Закриває `DESIGN_PRINCIPLES.md` §11 («Помилка — людською мовою, з дією») і частково §9
(«Логування не губить підхід офлайн»).

## Що зараз

Три випадки, перевірені в dev-стеку (знімки `shots/state-*`):

1. **Невідомий маршрут** `/does-not-exist` — порожній темний екран під навбаром. У `App.tsx`
   нема `<Route path="*">`.
2. **Неіснуюче тренування** `/workouts/<чужий або видалений id>` — «Завантаження…» назавжди.
   `pages/WorkoutFormPage.tsx:388`:
   ```tsx
   if (workoutQuery.isPending || exercisesQuery.isPending || progressionQuery.isPending || !workoutQuery.data) {
   ```
   Бекенд віддає 404, `isError` ніде не обробляється, умова `!workoutQuery.data` лишається true.
3. **Офлайн.** Після blur поля повторень без мережі через 2.5 с — лише спінер «Зберігаємо…»
   на кнопці. Банер «Не вдалося зберегти» з'являється, тільки коли `fetch` впаде, а в
   `api/client.ts` нема таймауту — на «підвислій» мережі в залі (сигнал є, пакетів нема) спінер
   може крутитись хвилинами.

Чому важливо: у залі поганий сигнал — норма, а застарілі посилання на тренування (з календаря,
закладки, після видалення) — звичайна річ.

## Що зробити

1. `pages/NotFoundPage.tsx`: заголовок «Сторінку не знайдено», одне речення, кнопка «До журналу»
   (`btn-primary`). Маршрут `path="*"` в `App.tsx` — всередині `ProtectedRoute`, щоб
   неавторизованого вело на login, як інші сторінки (або публічно — вирішити й пояснити в PR).
2. `WorkoutFormPage`: розділити «вантажиться» і «помилка». При `workoutQuery.isError`:
   - 404 (`ApiError` зі статусом 404 / кодом `not_found`) → «Тренування не знайдено. Можливо, його
     видалено» + посилання «До журналу»;
   - інша помилка → `translateApiError` + кнопка «Спробувати ще раз» (`refetch`).
   Те саме для `exercisesQuery`/`progressionQuery` — помилка, а не вічне завантаження.
3. **Офлайн-банер** (`components/OfflineBanner.tsx`, глобально під навбаром):
   «Немає мережі — зміни збережуться, щойно вона з'явиться». Показ за `navigator.onLine` +
   події `online`/`offline`. На `WorkoutFormPage` при `online` — `requestSave()`, якщо є
   незбережені правки (не ламати послідовність `flushSave`).
4. **Таймаут запиту** в `api/client.ts`: `AbortSignal.timeout(15_000)` (або свій контролер),
   помилка таймауту → той самий шлях, що мережева (банер «Не вдалося зберегти», без втрати
   введеного). Не скидати токен на таймаут (див. CLAUDE.md, «Auth: життя токенів» — мережева
   помилка refresh токен не скидає).
5. i18n-ключі в `en.json` і `uk.json` (`notFound.*`, `workout.notFound`, `offline.banner`,
   `errors.timeout`), звірити парність.

## Перевірка

- `/does-not-exist` → сторінка 404 з кнопкою, що веде на `/`.
- `/workouts/00000000-0000-4000-8000-000000000000` → «Тренування не знайдено» за ≤ 1 с.
- DevTools → Offline: змінити повторення → банер «Немає мережі»; Online → банер зникає,
  у мережі один `PUT …/exercises` з останнім станом.
- DevTools → Network throttling з великою затримкою (custom, 20 с): спінер зникає через ~15 с,
  з'являється «Не вдалося зберегти», введене на місці.
- `npm run build`, парність i18n.

## Як зроблено (відхилення, погоджені з користувачем)

- **Таймаут 20 с, не 15:** на `PUT …/exercises` 20 с уже стояли, тож одне число для всіх —
  типовий `timeout` axios-інстансу `api` і refresh-запиту (`REQUEST_TIMEOUT_MS`), не
  `AbortSignal.timeout`. CSV-імпорт — 120 с.
- **`requestSave()` на `online` не додавали:** автозбереження й так повторює збій на `online`.
  Натомість мутація збереження отримала `networkMode: 'always'` — офлайн TanStack ставив її на
  паузу (вічне «Зберігаємо…», а на `online` — застарілий PUT перед свіжим).
- Маршрут `*` — всередині `ProtectedRoute` (розлогіненого веде на login, як інші сторінки).
- Екрани помилки на сторінці тренування — лише при першому збої завантаження (`isLoadingError`):
  фоновий рефетч, що впав посеред тренування, форму з правками не підміняє.
