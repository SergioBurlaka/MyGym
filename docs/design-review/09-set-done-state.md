# 09 · Стан «підхід виконано»

Гілка: `feat/set-done-state`. Знахідка рев'ю F04. Фронтенд; бекенд — лише якщо обере
користувач (див. п. 1). **Рішення користувача:** змінює модель форми й автозбереження.
Закриває `DESIGN_PRINCIPLES.md` §9 («підхід, такий самий як минулого разу, — 1 тап»,
«Попередні значення видно в рядку підходу»).

## Що зараз

При старті з програми `POST /api/workouts { programId }` підставляє вагу й повторення з
останнього виконання (`findLatestWorkoutExercises`) — і **записує їх як справжні підходи**.
На сторінці тренування підставлене «10 · 10 · 9» нічим не відрізняється від уже зробленого
(знімок `shots/workout-live__mobile-390.jpg`).

Наслідки:
- під час тренування не видно, скільки підходів пройдено;
- автозавершення через 90 хв (`autoFinish.ts`) закриє тренування з підходами, яких не було, з
  минулими цифрами — це потрапить в історію;
- це тихо псує прогресію: сесія «як минулого разу» дає `sessionsSinceProgress + 1`, а неповне
  тренування, записане повністю, — хибне «без прогресу».

У лідерів категорії (Strong, Hevy) кожен рядок підходу має галочку.

## Варіанти — спитати користувача

**A. Лише фронтенд (менше змін).** Підставлені значення — плейсхолдери: поле порожнє, сірий
текст «10». Галочка 44×44 праворуч від поля: тап копіює плейсхолдер у значення (1 тап на
підхід «як минулого разу»). Будь-яка правка поля теж робить підхід «справжнім». Автозбереження
надсилає **лише справжні** підходи. Бекенд при старті з програми перестає вставляти підходи —
повертає «підказки» окремим полем (`suggestedSets`) → це вже зміна бекенду й MCP
(`start_workout`), тож A чисто фронтендовим не буде, якщо не тримати підказки на клієнті.

**B. Прапорець у БД.** `sets.done boolean` (міграція, CHECK не потрібен), старт з програми
вставляє підходи з `done=false`, прогресія й `findLatestWorkoutExercises` рахують лише `done`,
автозавершення видаляє/ігнорує `done=false`. Більше змін (бекенд, прогресія, MCP-схеми, тести),
але модель чесна й MCP теж бачить незроблене.

Рекомендація рев'ю — **B**: дані важливіші за форму, а прогресія живе на бекенді.

## Що зробити (після вибору)

1. Модель і міграція (для B) з тестами: `progression` ігнорує `done=false`; старт з програми;
   автозавершення; `PUT …/exercises` приймає `done`.
2. Рядок підходу: поле + галочка ≥ 44×44 (поруч зі степерами з 03 — перевірити, що влазить на
   375). Невиконаний — сірий текст значення, виконаний — `slate-100` + ✓ `good`.
3. Шапка вправи: «2 з 3 підходів» (`tabular-nums`).
4. Тап по галочці — у майбутньому старт таймера відпочинку (не в цьому завданні; лишити точку
   розширення).
5. Оновити CLAUDE.md («Автозбереження», «Автозавершення», «Програми»).

## Перевірка

- Старт з програми: підходи видно, але не позначені; закрити вкладку → через 90 хв
  автозавершення не записує непозначене в історію (тест `auto-finish.test.ts`).
- 1 тап на підхід «як минулого разу»; правка поля — підхід позначений.
- Прогресія: тренування з 2 позначеними з 3 — обсяг рахується за 2.
- Backend `npm test`, `npm run build`, MCP-тести, парність i18n.
