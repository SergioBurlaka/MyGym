# 13 · Банер «Є оновлення» для відкритої вкладки й PWA

Гілка: `feat/new-version-prompt`. Знахідка прод-рев'ю P02. Фронтенд + невелика зміна збірки.
Закриває `DESIGN_PRINCIPLES.md` §11 («Стани») і §9 (основний цикл не ламається посеред
тренування).

## Що зараз

На проді 2026-10-26 відкрита вкладка жила на `index-rIIV0DPA.js`, а сервер уже віддавав
`index-hHmcRmJi.js`. У старій версії були відкатані фікси аудиту 25 жовтня («1 / 4 sessions to
progress», біла кнопка на помаранчевому 3.1:1) — знімок
`shots/prod-journal__desktop-1440__stale-bundle.jpg`.

`frontend/nginx.frontend.conf` віддає `index.html` з `no-cache` — це вирішує лише **свіжий
запуск**. Відкрите вікно (а встановлений PWA зазвичай не закривають тижнями) нічого не
перевіряє і працює зі старим фронтендом проти нового API. Сервіс-воркера свідомо нема
(CLAUDE.md, PWA), тож механізм оновлення має бути свій.

## Що зробити

1. **Версія збірки.** Vite-плагін або крок `build`, що пише `dist/version.json`
   (`{ "version": "<git sha або час збірки>" }`), і та сама версія — у бандл через
   `define: { __APP_VERSION__: … }` у `vite.config.ts`. У `frontend/nginx.frontend.conf` —
   `location = /version.json` з `Cache-Control: no-cache` (як для `index.html`).
2. **Перевірка** (`hooks/useNewVersion.ts`): `fetch('/version.json', { cache: 'no-store' })` на
   `visibilitychange` (стала видимою), `focus` і раз на 30 хв, поки вкладка відкрита. Ті самі
   події вже слухає `api/client.ts` для refresh — не дублювати слухачі без потреби, але й не
   змішувати логіку з auth.
3. **Банер** (`components/UpdateBanner.tsx`, під навбаром, у стилі офлайн-банера з задачі 02):
   «Доступна нова версія MyGym» + кнопка «Оновити» (`location.reload()`).
   - **Під час активного тренування не перезавантажувати самим і не наполягати**: на
     `WorkoutFormPage` кнопка спершу викликає `flushSave()` і лише після успішного збереження
     робить reload. Якщо є незбережені правки й мережі нема — кнопку вимкнено з підказкою.
   - Банер можна закрити; повертається при наступній зміні версії.
4. i18n `update.available`, `update.reload`, `update.savingFirst` в `en.json` і `uk.json`,
   звірити парність.
5. Помилка `fetch('/version.json')` (офлайн) — тихо ігнорувати, банер не показувати.

## Перевірка

- Локально: `npm run build && npm run preview`, відкрити, змінити версію в `dist/version.json`
  руками, перемкнути вкладку туди-назад → з'являється банер; «Оновити» перезавантажує.
- На сторінці тренування з незбереженою правкою: «Оновити» спершу зберігає (один
  `PUT …/exercises`), потім перезавантажує; правка на місці.
- Офлайн: банер не з'являється, помилок у консолі нема.
- Після деплою на проді: відкрита до деплою вкладка показує банер ≤ 30 хв або одразу при
  поверненні у вкладку.
- `npm run build`, парність i18n.
