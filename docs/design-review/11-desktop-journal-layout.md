# 11 · Журнал на десктопі: дві колонки і підсумок тижня

Гілка: `feat/desktop-journal-layout`. Знахідка рев'ю F13. Фронтенд; бекенд — лише для
підсумку тижня, якщо наявних ендпоінтів не вистачить. Закриває `DESIGN_PRINCIPLES.md` §1
(«Десктоп — місце планування й аналізу. Не розтягнутий мобільний список у колонці»).

## Що зараз

На 1440 px журнал — мобільна композиція в колонці 992 px: календар консистентності на всю
ширину картки (~300 px заввишки), під ним список тренувань один під одним.
```
probe-craft.useOfWidth.contentFillRatio (journal · desktop-1440) = 0.69
```
Немає відповіді на «як пройшов тиждень» і «чи я сильнішаю» без кліку на кожну вправу.

## Що зробити

1. Від `lg`: сітка на дві колонки (`lg:grid lg:grid-cols-[minmax(0,1fr)_minmax(0,2fr)]`,
   можливо ширший контейнер сторінки — звірити з іншими сторінками).
   - **зліва (липка, `lg:sticky lg:top-…`)**: календар консистентності + картка «Цей тиждень»;
   - **справа**: список тренувань з пагінацією (як зараз).
   Мобайл і планшет — без змін.
2. **«Цей тиждень»**:
   - тренувань X з Y заплановано (розклад — `GET /api/settings`, дати — `GET /api/workouts/dates`,
     які вже тягне календар);
   - обсяг тижня проти минулого (`GET /api/progression/volume-by-category?weeks=2` — уже є);
   - «Спробуй більше»: N вправ (з overview, як блок на журналі зараз).
   Рекорди тижня — лише якщо 10 уже додав PR-дані; інакше пізніше.
3. Не дублювати запити: календар і підсумок беруть ті самі query keys.
4. i18n en/uk (`dashboard.week.*`).

## Перевірка

- 1440: дві колонки, `contentFillRatio` ≥ 0.85, ліва колонка не скролиться разом зі списком.
- 1366 і 1024: колонки не стискаються до нечитабельності (поріг `lg` чи `xl` — підібрати).
- 375: журнал як був (знімки до/після однакові).
- Мережа: жодного нового запиту, якщо дані вже в кеші календаря.
- `npm run build`, парність i18n.
