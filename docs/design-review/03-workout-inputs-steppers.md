# 03 · Поля тренування: 16 px, 44 px, степери

Гілка: `feat/workout-inputs-steppers`. Знахідка рев'ю F03. Лише фронтенд.
Закриває `DESIGN_PRINCIPLES.md` §5 (поля 16 px на мобайлі), §8 (зони ≥ 44×44) і §9 (зміна
ваги на крок — 1–2 тапи, без клавіатури).

## Що зараз

`styles/index.css` → `.input { … px-3 py-2 text-sm … }`. На `pages/WorkoutFormPage.tsx`:
- вага — `className="input w-32"`, `inputMode="decimal"` (~рядок 549);
- повторення — `className="input w-16 text-center"`, `inputMode="numeric"` (~рядок 599);
- «Назва» — `className="input w-48 py-1 text-sm"` (~рядок 431).

```
probe-craft.inputErgonomics (workout · mobile-390): 22 поля, 8 з них < 16 px і < 44 px
вага, повторення: fontPx 14, heightPx 38 · «Назва»: heightPx 30
inputmode правильний (decimal / numeric)
```

Наслідки:
- iOS Safari зумить сторінку при фокусі в полі з шрифтом < 16 px — на кожному тапі по вазі
  чи повтореннях;
- змінити вагу на крок (+1.25 кг) — тап → клавіатура → стерти → ввести → blur ≈ 4–6 дій;
  повторення ±1 — ≈ 3–4. Це повторюється 15–25 разів за тренування, однією рукою.

Крок ваги вже є в даних: `exercise.weightStepKg` (`types/index.ts`, з категорії вправи:
`large` 1.25, `small` 0.5 на бік).

## Що зробити

1. **Розмір (S).** На сторінці тренування поля ваги, повторень і «Назви» — `text-base` (16 px)
   і `h-11` (44 px). Не міняти глобальний `.input` на всьому сайті без потреби — або міняти
   свідомо (§5 каже 16 px для всіх полів на мобайлі; тоді `text-base sm:text-sm`). Вирішити й
   пояснити в PR.
2. **Степер ваги (M).** Кнопки «−» / «+» обабіч поля ваги, крок = `weightStepKg`, ≥ 44×44,
   проміжок ≥ 8 px. Не нижче 0, округлення до 0.01 (уникнути `0.1 + 0.2`). Зміна через степер
   → одразу `requestSave()` (як структурна зміна, не чекати blur).
   *Примітка:* §9 пише «степери ±2.5 кг» — це загальна цифра; у MyGym вага записується на бік,
   тож крок із категорії точніший. Уточнити формулювання в принципах.
3. **Повторення ±1 (M).** Варіанти — **спитати користувача**:
   - «−» / «+» біля кожного поля повторень (широко: 3 підходи × 3 елементи на 375 px — перевірити,
     що влазить);
   - або одна пара «−1 / +1», що діє на сфокусоване / останнє поле.
4. `aria-label` для кожної кнопки («Зменшити вагу на 1.25 кг», «Додати повторення в підході 2»),
   i18n en/uk. `tabular-nums` на полях ваги й повторень (§5).
5. Не ламати undo видалення підходу (ux-audit 07): степери стоять поруч із кнопкою «прибрати»
   — перевірити відступи.

## Перевірка

- Мобайл 375: усі поля тренування ≥ 16 px і ≥ 44 px (`probe-craft.inputErgonomics` → 0 порушень).
- «+» на вазі: 30 → 31.25 (large), 8 → 8.5 (small); один `PUT …/exercises` на тап (або злиті,
  але без паралельних запитів).
- Реальний iPhone або BrowserStack: фокус у полі ваги не зумить сторінку.
- `npm run build`, парність i18n.
