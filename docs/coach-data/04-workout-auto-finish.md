# Завдання 4: Статус і автозавершення тренування

## Мета
Незавершені тренування закриваються самі; статистика й тренер бачать лише
завершені; відкритим може бути лише одне тренування.

## Навіщо
Тренування 21.10 лишилось з `timeEnd = null`. Відкриті сесії псують тривалість,
пошук пропусків і «що було останнім».

## Контекст у репо
- `workouts.timeStart/timeEnd` виставляються автоматично (`startWorkout`,
  `finishWorkout`), не вручну.
- `POST /api/workouts/:id/finish`; MCP `finish_workout`.
- **Активність:** `PUT …/exercises` перезаписує підходи (delete + insert), тож
  `max(sets.createdAt)` / `max(workout_exercises.createdAt)` = час останнього
  збереження — готовий індикатор останньої активності без нової колонки.
- CSV-імпортовані тренування можуть мати `timeStart/timeEnd = null` — це
  **завершені історичні**, а не відкриті.

## Що зробити

### БД
1. `workouts`: `status text not null default 'completed'` (CHECK `in_progress |
   completed | abandoned`), `endReason text null` (`manual | auto_idle |
   auto_next_workout`).
2. Міграція наявних рядків: `timeEnd` є → `completed/manual`; `timeEnd` null і
   `timeStart` null (імпорт) → `completed`, `endReason` null; `timeEnd` null,
   `timeStart` є → обробити правилом п. 4 одразу в міграції.
3. Частковий унікальний індекс: один `in_progress` на `userId`.

### Бекенд
4. Правило (функція `autoFinishStale(userId?)`, «ліниво» на початку
   `startWorkout`, `listWorkouts`, `coach/summary` + за бажанням інтервал у
   процесі бекенду): `in_progress` і остання активність старша за
   `WORKOUT_IDLE_FINISH_HOURS` (env, default 3) → `completed` (є хоча б один
   підхід з reps > 0) або `abandoned` (нема), `timeEnd` = остання активність
   + 2 хв, `endReason = 'auto_idle'`.
5. `startWorkout`: відкрите тренування закривається з `endReason =
   'auto_next_workout'` у тій самій транзакції (пам'ятати gotcha `tx.query`).
6. `finishWorkout` ідемпотентний: повторний виклик повертає той самий результат.
7. Статистика й прогресія (`progression.service.ts`, `volume-by-category`,
   coach summary): рахувати `completed` і поточне `in_progress`, ніколи `abandoned`.
   Тривалість автозакритих — позначка «орієнтовна».
8. Тести: правило (межа 3 год), старт нового закриває старе, ідемпотентне
   завершення, `abandoned` не потрапляє в прогресію, міграція імпортованих.

### MCP
9. `finish_workout`: `idempotentHint: true`; у відповідях тренувань — `status`, `endReason`.

### Фронтенд
10. Журнал: бейдж «Завершено автоматично», тривалість зі знаком «≈» і підказкою
    «Тривалість орієнтовна: тренування не завершили вручну».
11. Банер на журналі при відкритому тренуванні з минулого: «Незавершене
    тренування · 21 жовтня, 10:35 · 18 підходів» → «Продовжити» / «Завершити».
12. «+ Нове тренування» при відкритому: діалог «У тебе є незавершене тренування
    від 21 жовтня. Завершити його і почати нове?» → «Завершити і почати» / «Скасувати».
13. en/uk.
