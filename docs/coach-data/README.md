# Дані для AI-тренера: план реалізації

Набір завдань для Claude Code, щоб тренер у Claude-чаті (скіл
`mygym-bodybuilding-coach`, через MCP) міг повноцінно аналізувати тренування.
Кожен файл — окреме самодостатнє завдання: відкрий новий чат Claude Code в
корені репо і напиши «виконай docs/coach-data/0X-….md» (або `/feature` + вміст файлу).

- **Дослідження й обґрунтування** (бест практис, як роблять Hevy/Boostcamp/RP/
  WHOOP/Oura, UI-тексти): `RESEARCH.md` у цій папці.
- Логіка прогресії (повернення після перерв, плато, малі групи) — документ
  «MyGym: нова логіка прогресії»: https://claude.ai/artifact/PnssynjvLHM29FdAMthn7t
- ТЗ на годинник і ваги (Health Connect) — «ТЗ: інтеграція розумних ваг і
  годинника в MyGym»: https://claude.ai/artifact/Jnq6hdiYh3bragn8hfA2pK

> Набір написано 2026-10-22 за аналізом реальних даних (тренування 8–21.10):
> тренер не зміг прочитати історію (`list_recent_workouts` віддав ~160 КБ),
> не бачив RIR, обсягу на м'яз і причин пропусків.

## Рішення, які треба прийняти до старту

1. **Безпечний запис через MCP (пункт 1).** 2026-10-21 вирішено лишити
   `log_workout_exercises` (= `PUT …/exercises`, «замінити все») і не робити
   merge-ендпоінт. Дослідження радить додати інструмент, що лише **додає**
   підходи (`log_sets`), бо агент може повторити виклик після тайм-ауту.
   Варіанти — у `01-rir-per-set.md`, дочекатися вибору.
2. **Шкала RIR:** рекомендовано чипи `0 · 1 · 2 · 3 · 4 · 5+` замість радіокнопок
   1–5 (обґрунтування — `RESEARCH.md`, пункт 1).
3. **Поріг автозавершення** (пункт 4): 3 год без активності — пропозиція, винести в конфіг.

## Загальні правила для всіх завдань

- Спершу прочитати `CLAUDE.md` — стек, конвенції, gotcha-и. Стек не змінювати
  (Fastify/Zod/Drizzle/Postgres, React/Vite/Tailwind/TanStack Query, i18n en/uk).
- Виконувати через `/feature` (гілка → план з «ок» → коміти → рев'ю → тести).
- **Бізнес-логіка — у бекенді.** MCP-сервер лишається тонким stateless-проксі:
  новий інструмент = новий ендпоінт бекенду + реєстрація в `mcp-server/src/tools/*.ts`
  (+ тест у `mcp-server/test/`). Схеми входу MCP дзеркалять бекенд із `z.coerce`.
- **Відповіді MCP компактні:** людські назви замість UUID там, де можна; без
  вкладених повних об'єктів вправ; `readOnlyHint`/`destructiveHint`/`idempotentHint`
  явно на кожному інструменті; помилки валідації — `isError` з текстом, як виправити.
- Жодних ламаючих змін для веб-клієнта (автозбереження форми тренування,
  журнал з пагінацією, календар консистентності мають працювати як раніше).
- Нові nullable-колонки — без перезапису даних; міграція Drizzle в тому ж
  коміті, що й `schema.ts`; перезняти `docs/db/schema.sql`, оновити `docs/db/ARCHITECTURE.md`.
- Бекенд: `npm test` і typecheck зелені; `mcp-server`: `npm test`; фронтенд: `npm run build`.
- Нові UI-тексти — у `frontend/src/i18n/locales/{en,uk}.json` (дзеркальні ключі),
  коди помилок через `translateApiError`.
- Після завдання — оновити `CLAUDE.md` і стан у таблиці вище.
- **Не комітити в `main` і не пушити туди**: push у `main` = деплой на прод.
