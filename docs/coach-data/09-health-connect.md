# Завдання 9: Годинник і ваги через Health Connect

## Мета
Тренер у Claude-чаті через MCP бачить сон, пульс спокою, HRV і вагу як тренд
проти власної норми, і статус готовності (зелений / жовтий / червоний) за
пояснюваними правилами.

## Важливо
- Google Fit API підтримується лише до кінця 2026 — не використовувати.
- Health Connect живе на Android-телефоні: бекенд отримує дані лише через
  **Android-компаньйон** (або майбутній React Native MyGym — див.
  `docs/mobile-prep/`). Компаньйон — окремий проєкт; це завдання — бекенд +
  MCP + контракт API для компаньйона.
- Повне ТЗ (архітектура, дозволи, приватність, ризики, критерії):
  https://claude.ai/artifact/Jnq6hdiYh3bragn8hfA2pK — прочитати перед стартом.

## Залежності
Завдання 8 (`readiness_checks`; сон з пристрою підставляється в анкету).

## Що зробити

### Бекенд (частина 1 — у цьому репо)
1. Таблиці: `health_devices` (джерело, модель, `lastSyncAt`), `health_records`
   (сирі записи, unique `(userId, deviceId, recordId)`), `health_daily`
   (`localDate`, `sleepMin`, `rhrMedian`, `hrvLnRmssd`, `weightKg`,
   `bodyFatPct`, `steps`, `sources jsonb`, `syncedAt`), `readiness_daily`
   (`status`, `signals jsonb`, `baselines jsonb`, `algoVersion`).
2. `POST /api/health/ingest` — пакет до ~500 записів, ідемпотентний,
   валідація діапазонів (пульс 25–220, вага 25–300 кг), rate limit; приймає
   PAT/OAuth-токен **окремого** призначення (обговорити: новий scope
   `health:write` vs окремий тип токена).
3. Перерахунок `health_daily` для зачеплених дат; бази й сигнали (чисті
   функції, юніт-тести на кожен поріг):
   - пульс спокою: медіана за 14–30 днів; +3 уд/хв одна ніч → жовтий;
     ≥+4 дві ночі поспіль → червоний;
   - сон: ≤6 год або на 1–1,5 год менше норми дві ночі поспіль → червоний;
   - HRV (ln rMSSD): 7-денне середнє нижче діапазону за 30–60 днів → м'який
     сигнал (за <30 днів даних — «ще без бази»);
   - вага: 7-денне середнє; незапланований спад >1–1,5% за 1–3 дні → червоний.
   Статус дня: 0 червоних → зелений, 1 або лише жовті → жовтий, 2+ → червоний.
   Симптоми з анкети (завдання 8) мають пріоритет.
4. `GET /api/readiness/today`, `GET /api/health/daily?from&to`,
   `GET /api/health/sync-status`, `DELETE /api/health/data` (лише сесія).
5. `coach/summary` — останній статус готовності з правилом, що спрацювало.

### MCP
6. `get_readiness(from, to)` → денні агрегати, відхилення від норми, джерело,
   `status`, `rule`, `inputsMissing`. `readOnlyHint: true`. Сирі записи не віддавати.
   Узгодити окремий дозвіл/scope `health:read` у власному OAuth-сервері.

### Фронтенд (мінімум)
7. Рядок статусу на аркуші анкети: «✓ Готовий тренуватися за планом» /
   «◐ Тренуйся, але без рекордів» / «◯ Сьогодні пріоритет — відновлення» +
   причина одним рядком («Пульс спокою +4 уд/хв дві ночі поспіль»), стан
   «Вивчаємо твою норму: 4 з 14 ночей», дрібно «Не є медичною порадою».
8. «Інтеграції» → блок «Годинник і ваги»: статус синхронізації, «Видалити дані здоров'я».

### Компаньйон (частина 2 — окремий проєкт, не в цьому завданні)
9. Kotlin + Health Connect SDK + WorkManager: читання `SleepSession`,
   `RestingHeartRate`, `HeartRateVariabilityRmssd`, `Weight`, `BodyFat`,
   `Steps`; Changes API; черга Room; `POST /api/health/ingest`. Ставиться APK
   без Google Play для особистого користування.

## Критерії готовності
- Тести на всі пороги; ingest ідемпотентний; видалення прибирає всі `health_*`.
- CLAUDE.md: таблиці, ендпоінти, правила, приватність.
