# 07 · Кнопка видалення підходу

Гілка: `fix/remove-set-button`. Знахідка аудиту 02. Лише фронтенд.

## Що зараз

`pages/WorkoutFormPage.tsx` (~рядки 498–517): поруч із кожним полем повторень —
`<button title="Remove set">×</button>` без фону й відступів.

```
розмір 11×24 px · відступ до поля повторень 4 px · 20 таких кнопок на одному тренуванні
колір text-slate-500 (3.43:1) · WCAG 2.5.8 вимагає ≥ 24×24
```

Чому це важливо саме тут:
- у залі, однією рукою, між підходами — найлегше промахнутись саме по ній;
- `removeSet` одразу викликає `requestSave()` — підхід зникає й зберігається миттєво, без undo;
- «×» поруч із числом читається як знак множення («12 ×»), а не як «видалити».

## Що зробити

1. Іконка «−» або кошика (SVG, `aria-hidden`) + `aria-label={t('workout.removeSetAria',
   { set: i + 1 })}`. Зона натиску ≥ 44×44 (`p-2.5` або `min-h-11 min-w-11`), відступ від
   поля ≥ 8 px. Колір — `text-slate-400`, hover `text-red-400`.
2. **Undo замість підтвердження** (підтвердження на кожен підхід дратуватиме): тостової
   системи в проєкті нема, тому мінімально — на місці видаленого підходу рядок
   «Підхід 3 видалено · Повернути» на 5 с. `requestSave()` викликати лише після того, як
   рядок зник (або при виході зі сторінки — cleanup-ефект уже зберігає незбережене).
   Не ламати послідовність `flushSave`.
3. Видаляти лише останній підхід? — **спитати користувача**: це найпростіший захист
   (кнопка одна, в кінці рядка), але не дає прибрати підхід з середини.
