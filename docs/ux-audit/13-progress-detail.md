# 13 · Деталь вправи на «Прогресі»: той самий статус, що в плитці

Гілка: `fix/progress-detail-status`. Знахідка раунду 2: N02 (+ залишок 17 з першого аудиту).

## Що зараз

`pages/ProgressPage.tsx` (~рядки 95–130). Перша плитка — найтерміновіша, а деталь під нею
називає той самий стан спокійним:

```
Плитка:  «Підняття ніг на прес (шведська стінка) · 4 з 5 тренувань»
Деталь:  <ProgressionBadge suggestion="ok"> → «Прогрес у нормі»
         progressionMessage(…)              → «Прогрес у нормі.»
         Востаннє: 2026-10-27               ← selected.lastWorkoutDate без formatDate
         Тренувань без прогресу: 4 / 5      ← `${sessionsSinceProgress} / ${tryMoreAfterWorkouts}`
```

Бекенд віддає `suggestion: "ok"`, бо поріг 5 ще не досягнуто — дані правильні, неправильне
слово для них. Голий дріб і ISO-дата — те, що перший аудит прибрав з усіх інших екранів.

## Що зробити

1. Біля назви вправи замість `ProgressionBadge` для `ok` показувати `TryMoreStatusBadge`
   з `tryMoreStatus(selected, null)` — той самий вигляд, що в плитці («До «Спробуй більше» ·
   4 з 5 тренувань» із сегментами). Для `increase_weight` / `start_adding_weight` / `try_more`
   лишити як є (це дії).
2. Речення `progressionMessage` для `ok` прибрати (воно дублює бейдж) або замінити на
   корисне: «Ще 1 тренування без прогресу — і нагадаємо спробувати більше» (новий ключ).
3. «Востаннє» → `formatDate(selected.lastWorkoutDate, { day: 'numeric', month: 'long' })`.
4. «Тренувань без прогресу» → `t('progressStatus.ofWorkouts', …)`: «4 з 5 тренувань».
5. Для вправ без ваги не показувати картки «Робоча вага» і «Розрахунковий 1ПМ» — зараз це
   дві картки з текстом «вправа без ваги».

## Перевірка

- Вибрати «Підняття ніг на прес»: біля назви — «4 з 5 тренувань», «Востаннє 27 жовтня»,
  під статистикою — два графіки (повторення й обсяг), не чотири.
- Вибрати вправу зі статусом «Час додати вагу» — бейдж дії лишився.
- `npm run build` без помилок.
