# 02 · Наступна програма в меню «+ New workout»

Знахідка аудиту 05. **Спершу спитати користувача — це перегляд його рішення.**

## Контекст і конфлікт із попереднім рішенням

`GET /api/programs/suggestion` (`getSuggestedProgram`, `programs.service.ts`) рахує наступну
програму в ротації, але фронтенд його не використовує. У CLAUDE.md записано: користувач
**свідомо попросив прибрати авто-пропозицію з кнопки** (рішення 2026-09-20), і в
`NewWorkoutButton.tsx` є коментар «No program is pre-selected or highlighted here».

Аудит (2026-10-25) показав, що без підказки меню йде в порядку створення
(`orderIndex`), а не ротації:

```
GET /programs/suggestion → "прес + підтягування"
Меню: Blank workout · «Підняття ніг на прес» · «Б» · «А» · «прес + підтягування»
```

## Питання до користувача (до коду)

Варіанти, від найм'якшого:
- **(а)** лише маленька мітка «далі» біля запропонованої програми, порядок не змінюється,
  нічого не вибирається автоматично;
- **(б)** запропонована програма першою в списку з міткою, без авто-вибору;
- **(в)** лишити як є — тоді закрити цей пункт і позначити в README як «відхилено».

## Що зробити, якщо (а) або (б)

1. `useProgramSuggestionQuery` (вже є в `shared/api/programs/hooks/`) у `DashboardPage.tsx`,
   передати `suggestedProgramId` у `NewWorkoutButton`.
2. `NewWorkoutButton.tsx`: мітка `t('newWorkoutButton.next')` («далі» / «next») біля
   програми; для (б) — ще й перемістити її на початок `entries`.
3. Інвалідувати ключ suggestion після старту тренування (`useStartWorkoutMutation`),
   інакше мітка застаріє.
4. Оновити коментар у компоненті й пункт «UI-нюанс» у CLAUDE.md (нове рішення з датою).

## Перевірка

Стартувати тренування з програми А → у меню мітка переходить на наступну за ротацією.
