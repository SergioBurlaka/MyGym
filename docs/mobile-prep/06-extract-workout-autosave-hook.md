# Завдання 6: Винести чергу автозбереження і `scheduleOn()` зі сторінок у хуки/чисті функції

## Мета
Відокремити платформонезалежну бізнес-логіку від DOM-компонентів, щоб у майбутньому
вона переїхала в спільний пакет і використовувалась і вебом, і React Native без копіювання.

## Навіщо
Черга автозбереження (`flushSave` + `pendingSaveRef` + `saveTick` + `blocksRef`) живе
всередині `WorkoutFormPage.tsx` (~520 рядків). `PUT /api/workouts/:id/exercises`
перезаписує **всі** вправи тренування, тому збереження мусять бути строго послідовними —
ручна копія цієї логіки в RN-екрані — найпростіший спосіб повернути баг з дублюванням
підходів. Те саме — `scheduleOn()` з календаря консистентності.

## Контекст
- CLAUDE.md, розділ «Автозбереження тренування» — детальний опис поведінки, яку
  **треба зберегти 1:1** (blur-збереження, структурні зміни одразу, збереження при unmount,
  мовчазний пропуск вправи без повторень, банер помилки, що зникає після успіху,
  спінер на кнопці).
- `frontend/src/pages/WorkoutFormPage.tsx`, `frontend/src/components/ConsistencyCalendar.tsx`.

## Що зробити
1. Хук `useWorkoutAutosave` (напр. `frontend/src/shared/workout/useWorkoutAutosave.ts`):
   вхід — id тренування, поточні blocks, функція збереження (мутація); вихід —
   `requestSave()`, `flushNow()`, `isSaving`, `isDirty`, `error`. Жодного DOM/`window`
   усередині. Логіку «чи можна зберегти» (валідація порожніх вправ, мапінг blocks → payload)
   винести в **чисті функції** поруч.
2. `scheduleOn()` і обчислення стану клітинки (`trained_planned`/`trained_extra`/
   `missed_planned`/`rest`, «сьогодні завжди нейтральне») — у чисті функції
   (напр. `frontend/src/shared/schedule/consistency.ts`), компонент лише рендерить.
3. `WorkoutFormPage.tsx` і `ConsistencyCalendar.tsx` використовують нове; поведінка не змінюється.
4. Нові модулі не імпортують нічого з `react-dom`, `react-router-dom`, Tailwind, `window`/`document`.

## Обмеження
- Чистий рефакторинг: ніяких змін UX, API чи бекенду.
- Тести до цих модулів — у завданні 9 (але пиши код так, щоб чисті функції було легко тестувати).

## Перевірка
- `npm run build` у `frontend/` без помилок.
- Ручний чек-лист (дай його мені): правка повторень + blur → один PUT; швидкі правки під
  час збереження → рівно ще одне збереження з найсвіжішим станом; додати/прибрати підхід;
  вихід зі сторінки з незбереженою правкою; порожня вправа не зберігається мовчки;
  календар показує ті самі кольори, що й до рефакторингу.
- CLAUDE.md: оновити розділи «Автозбереження» і «Календар консистентності» — де тепер живе логіка.
