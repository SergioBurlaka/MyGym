## Перетин з уже зробленим auth (PAT, OAuth, Google)

У бекенді вже кілька механізмів автентифікації (див. `CLAUDE.md`):
сесійний JWT + refresh-cookie (веб), вхід через Google (серверний OAuth-flow з
редиректами й cookie), PAT `mygym_pat_…` і OAuth-токени `mygym_oat_…` для
MCP-клієнтів (обидва в `api_tokens`, `authMethod = 'pat'`). Тому:
- завдання 2: mobile-режим refresh — ще один, окремий механізм; `authenticate.ts`
  і далі приймає всі наявні. Google-вхід для мобільного — окремий пункт завдання;
- завдання 3: видалення акаунта прибирає й `api_tokens`, `oauth_*`, `refresh_tokens`;
  акаунт, створений через Google, пароля не має — підтвердження інше;
- завдання 5: перевірка `X-Client-Version` не зачіпає запити MCP-сервера / PAT / OAuth,
  бо вони йдуть без `X-Client: mobile`.

## Загальні правила для всіх завдань

- Спершу прочитати `CLAUDE.md` — там стек, конвенції й gotcha-и. Стек не змінювати
  (Fastify/Zod/Drizzle/Postgres, JWT, React/Vite/Tailwind/TanStack Query).
- Виконувати через `/feature` (гілка → план з «ок» → коміти → рев'ю → тести).
- Перед змінами коротко описати план і компроміси (чому саме так) і дочекатися «ок».
- Жодних ламаючих змін для поточного веб-клієнта.
- Бекенд: `npm test` і typecheck зелені; фронтенд: `npm run build` без помилок.
- Нові UI-тексти — у `frontend/src/i18n/locales/{en,uk}.json` (дзеркальні ключі).
- Після завдання — оновити відповідний розділ `CLAUDE.md`.
- **Не комітити в `main` і не пушити туди**: push у `main` запускає деплой на прод.
