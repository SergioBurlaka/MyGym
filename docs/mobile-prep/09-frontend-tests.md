# Завдання 9: Перші тести фронтенду (Vitest)

## Мета
Додати Vitest у `frontend/` і покрити юніт-тестами платформонезалежну логіку,
яка в майбутньому стане спільною для вебу й React Native.

## Навіщо
Зараз на фронтенді тестів немає взагалі. Логіка, яку переносимо в спільні пакети,
має бути захищена тестами **до** переносу — тоді та сама батарея тестів перевірятиме
обидві платформи.

## Залежність
Завдання 6 і 7 (винесені хуки/чисті функції і ядро API-клієнта).

## Що зробити
1. Налаштувати Vitest у `frontend/` (конфіг у `vite.config.ts` або окремо; environment
   `node` для чистих функцій, `jsdom`/`happy-dom` — лише там, де потрібен хук),
   `@testing-library/react` для `renderHook`. Скрипти `test`, `test:watch` — як у бекенді.
2. Тести:
   - `utils/progressionMessage.ts` — усі `suggestion`, дні vs сесії, en/uk;
   - `utils/weight.ts` — `formatDate`/`formatDuration`/`formatTotalWeight` для обох мов;
   - `utils/labelColor.ts` — детермінованість, однаковий колір для однакової мітки;
   - `utils/apiError.ts` — відомий код, невідомий код, мережева помилка;
   - консистентність-календар (чисті функції з завдання 6): розклад з історії, що діяв
     **тоді**; 4 стани; «сьогодні завжди нейтральне»;
   - `useWorkoutAutosave` (fake timers + mock-мутація): послідовність збережень, правка
     під час збереження → рівно одне додаткове збереження з найсвіжішим станом,
     пропуск порожньої вправи, скидання помилки після успіху;
   - ядро API-клієнта (завдання 7, з фейковими `TokenStore`/`AppLifecycle`): single-flight
     (два паралельні 401 → один refresh), мережева помилка refresh не скидає сесію,
     справжній 401 refresh → `onSessionLost`.
3. Скрипт перевірки дзеркальності ключів `en.json`/`uk.json` (якщо ще не тест) — оформити як тест.
4. CI (`.github/workflows/deploy.yml`): у джобі `frontend-build` додати `npm test` перед
   build, щоб `deploy` залежав і від тестів фронтенду.
