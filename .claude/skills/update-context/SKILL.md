Інкрементально оновлює кореневий `CLAUDE.md`: читає реальні зміни коду →
править лише зачеплені секції. Не переписує файл цілком і не займається
косметикою — лише факти, яких торкнулася ця дельта.

Аргумент `$ARGUMENTS` — `since:<ref>` (база diff). Без нього: `git diff HEAD` +
`git diff --cached` (незакомічене) або, якщо чисто, `git diff HEAD~1..HEAD`.

## Крок 1 — Зібрати дельту

```bash
git status --porcelain
git diff HEAD -- backend/ frontend/ docker-compose*.yml
```

Якщо дельти нема — сказати «CLAUDE.md актуальний» і вийти.

## Крок 2 — Зіставити змінені шляхи ↔ секції CLAUDE.md

| Змінений шлях | Секція CLAUDE.md |
| :-- | :-- |
| `backend/src/db/schema.ts` | ## Модель даних |
| `backend/src/modules/progression/**` | ## Логіка прогресії |
| `backend/src/modules/import/**`, `importColumns.ts` | ## CSV-імпорт |
| `backend/package.json`, `frontend/package.json` (нові/змінені залежності стеку) | ## Стек |
| `docker-compose*.yml`, `**/Dockerfile*`, `frontend/vite.config.ts`, `.env*` | ## Стан проєкту → Windows-специфічні нюанси / інфраструктура |
| `frontend/src/shared/api/**`, `**/hooks/use*Query.ts`, `**/hooks/use*Mutation.ts` | ## Стек → опис frontend-конвенції (якщо змінився сам патерн, не окремий ресурс) |
| нові модулі backend (`backend/src/modules/<new>/`) | ## Модель даних або новий підрозділ у ## Стан проєкту, залежно від суті |

Секцій, яких зміни не торкнулися, — не чіпати.

## Крок 3 — Оновити лише зачеплені секції через Edit

Для кожної зачепленої секції:
- прочитай реальний змінений код (не тільки diff-контекст наосліп) — нові поля,
  правила, ендпоінти;
- внеси точкову правку в CLAUDE.md через `Edit` (не `Write` всього файлу);
- пиши українською, у стилі решти файлу (стисло, конкретно, без вступів);
- лише підтверджене з коду; невідоме — не вигадуй, або познач одним словом
  проблему, яку варто уточнити в користувача;
- значні технічні рішення чи gotchas — у стилі вже наявних приміток
  («Windows-специфічні нюанси» — приклад формату: коротко проблема → коротко фікс).

## Крок 4 — Підсумок

```
Оновлено CLAUDE.md:
- <секція> ← <файли, що спричинили правку>
- ...
```

Якщо torkнулась `## Стан проєкту`, а сама фіча ще не перевірена наживо (dev-стек,
curl, UI) — не пиши "перевірено", напиши, що саме лишилось перевірити.

## Правила

- **Інкрементально:** тільки секції, яких торкнулися зміни. Без повної регенерації.
- **Anti-hallucination:** лише факти з коду; невідоме не вигадувати.
- Це не заміна ручного рев'ю — після виклику коротко покажи користувачу, що саме
  змінилось у CLAUDE.md (diff), а не просто скажи "оновив".
