# Шаблони тренувань і програми

**Дані програми.** `programs.orderIndex` — черга ротації (A→Б→A…), присвоюється в кінець при
створенні. `program_exercises`: `targetSets`, `orderIndex`, `lockSets` (фіксована кількість
підходів, міграція 0027), `tryMoreAfterWorkouts` (nullable — поріг `try_more` вправи в цій програмі,
`null` = стандарт категорії, див. `.claude/rules/progression.md`). Порогу на всю програму нема —
`programs.try_more_after_workouts` видалено міграцією 0028 **без переносу** у вправи (рішення
користувача). Ваги штанги й гантелей `program_exercises` **не** зберігає: вона підтягується з
останнього фактичного виконання вправи при старті тренування. Виняток — `extraWeightKg`
(міграція 0030): обтяження вправи з **власною вагою**, з яким стартує тренування (`null` = без
ваги). Zod — `extraWeightKg` 0–500, nullable, optional (`programs.schema.ts`); `programExerciseRows`
(`programs.service.ts`) зберігає його лише для `equipment = 'bodyweight'` і лише > 0, інакше
`null`. Фільтр — тільки при збереженні: змінений пізніше снаряд вправи рядок не перераховує.
Одна вправа один раз у програмі (UNIQUE); дубль у `POST/PUT /api/programs` → 400
`validation_error` / `duplicate_exercise` ще в Zod.

**Шаблони тренувань (чергування програм А/Б):** користувач тренується за
чергуванням (напр. програма А і програма Б через раз), і не хоче щоразу
вручну додавати одні й ті самі вправи. Реалізовано через `workouts.programLabel`
(довільний текст, не enum — юзер сам вирішує назви):
- `PATCH /api/workouts/:id` — виставити/змінити мітку на будь-якому тренуванні
  (поле «Мітка» на `WorkoutFormPage`, під датою).
- `GET /api/workouts/templates` — по одному найновішому тренуванню на кожну
  унікальну мітку користувача (дата + перелік назв вправ, для прев'ю).
- `POST /api/workouts` приймає `{ programLabel?, copyFromWorkoutId? }` — копіює
  вправи+ваги (**без підходів** — повторення щоразу нові) з вказаного
  тренування в межах однієї транзакції.
- Dashboard: кнопка «+ Нове тренування» — `components/NewWorkoutButton.tsx`,
  спливне меню «Порожнє» + по одній опції на мітку (з датою й превʼю вправ).
  Меню не показується, якщо міток ще нема (одразу порожнє тренування).
- Кольорове кодування карток у журналі — `utils/labelColor.ts`: детермінований
  хеш мітки → колір з палітри (sky/amber/violet/emerald/rose/cyan), однакова
  мітка завжди отримує той самий колір. Не хардкод на «А»/«Б» — працює для
  будь-якої кількості довільних міток.
- Фактичне правило користувача: тренування зі становою тягою
  без присідань = А, з присіданнями без станової = Б. Застосовано ретроактивно
  до існуючих даних (24 тренування однозначно розмічені). **9 тренувань
  01–17.07.2026 мають і станову, і присідання одночасно** (інша структура
  програми на той момент, ще без A/Б-спліту) — свідомо лишені без мітки,
  бо правило для них неоднозначне.
- **Gotcha:** `startWorkout` — транзакційний; читати щойно вставлений рядок
  назад треба через `tx.query`, а не через звичайний `db`/`getWorkout()` —
  інакше читаєш ще не закомічені дані з окремого з'єднання й отримуєш
  `undefined`.

**Програми (backend/src/modules/programs/):** окремо від "Шаблонів тренувань"
вище — іменована програма (`programs`/`program_exercises`) створюється
ЗАЗДАЛЕГІДЬ, вручну (вправи + `targetSets`), і не потребує жодної попередньої
історії тренувань (на відміну від `programLabel`-шаблону, який можна
застосувати лише ПІСЛЯ того, як тренування з такою міткою вже було). Для
нового користувача без жодного тренування це єдиний спосіб стартувати з
готового набору вправ.
- CRUD: `GET/POST /api/programs`, `GET/PUT/DELETE /api/programs/:id`.
- Ротація A/Б (і далі по колу для 3+ програм): `programs.orderIndex`
  присвоюється автоматично в кінець черги при створенні. `GET
  /api/programs/suggestion` (`getSuggestedProgram` у `programs.service.ts`) —
  дивиться останнє фактично стартоване з `programId` тренування й повертає
  наступну по колу програму; якщо жодного ще не було або остання
  використана програма вже видалена — повертає першу (`orderIndex=0`). Це
  лише підказка, не обмеження: бекенд не валідує повторний вибір тієї самої
  програми поспіль.
  **UI-нюанс:** цей ендпоінт реалізований і протестований, але фронтенд його
  НЕ використовує — `NewWorkoutButton` показує звичайний випадаючий
  список програм без виділення "наступної" (рішення користувача — без
  авто-пропозиції на кнопці).
- Автозаповнення: `POST /api/workouts { programId }` (`startWorkout`) копіює список вправ
  програми. **Вагу** штанги й гантелей (диски/гантелі, `weightUnits`, `barKg`) підтягує з
  **останнього фактичного виконання** кожної вправи (в будь-якому тренуванні
  користувача) — `findLatestWorkoutExercises` у `workouts.service.ts`: один
  `DISTINCT ON (exercise_id)`, вставка вправ пакетом. Вправа з **власною вагою** бере
  обтяження з програми (`extraWeightKg` через `storedLoad`); `null` → без ваги, минулий раз
  ігнорується — програма тут єдине джерело, тож прибране в програмі справді прибране. Тести —
  `test/program-extra-weight.test.ts`. **Підходів не створює**:
  повторення сторінка показує плейсхолдерами з `previous`, а `targetSets`
  лише задає кількість клітинок — префіл справжніми повтореннями робив би
  покинуте тренування фейковою сесією в історії. Рахуються лише виконання **з
  підходами** (вправа, додана й не записана, чи копія з шаблону ваги могла не мати).
  Вправа двічі в одному тренуванні — береться нижча в списку. Тести —
  `test/batch-queries.test.ts`. `workouts.programId` фіксує зв'язок;
  назва програми так само стає `workouts.programLabel` цього тренування. Перейменування програми (`updateProgram`, та сама транзакція) переносить нову назву
  на її тренування, де мітка досі дорівнює старій назві; змінені вручну мітки й
  тренування без `programId` не чіпаються (рішення користувача — інакше
  старі картки лишались би зі старою назвою й іншим кольором).
- Видалення програми — справжнє (`DELETE`), каскадить `program_exercises`;
  `workouts.programId` існуючих тренувань стає `null` (сам запис, вправи й
  підходи не чіпаються), вправи в загальному списку "Вправи" не зачіпаються
  (FK `program_exercises.exerciseId` — `no action deferrable`, вправу з програми не видалити).
- Сторінка `/programs` (`ProgramsPage.tsx`, пункт «Програми» в навбарі) —
  список програм + форма
  створення/редагування (на весь екран, макет C — див. "UI (`ProgramsPage.tsx`)" у `.claude/rules/progression.md`):
  назва, вправи з крокером підходів, замком і порогом, реордер через меню «⋯». Вправа з
  власною вагою має ще поле `programs.form.extraWeightLabel` («Додаткова вага, кг», плейсхолдер
  `workout.weightPlaceholderNoWeight`) з підказкою `programs.form.extraWeightHint`; порожнє = `null`, кома =
  крапка (`parseKg`), поза 0–500 — `programs.form.errorExtraWeight` без запиту. Для інших
  снарядів поля нема, у запиті — `null`.
  Картка програми (`ProgramCard`): назва, кількість вправ, смітник; рядок вправи — назва
  `×targetSets` + замок (`LockIcon`, `programs.setsLocked`), якщо `lockSets`. Статусу прогресу
  на картці нема — див. `.claude/rules/progression.md`.
  **Тап будь-де по картці відкриває форму редагування** — патерн «клікабельна картка», як
  `WorkoutCardLink` журналу (`.claude/rules/journal.md`): назва в `<h3>` — `<button>`
  (`aria-label` `programs.editProgramAria` з назвою), розтягнутий на всю картку
  (`after:absolute after:inset-0`, картка `relative`, `hover:border-accent/50`), кільце фокусу — на
  `::after` навколо картки. Меню дій нема: єдина інша дія — смітник 44 px (`h-11 w-11`,
  `-mr-2 -mt-2`), `aria-label`/`title` `programs.deleteProgramAria` з назвою, `aria-expanded` =
  відкрите підтвердження; `Popconfirm` `programs.deleteConfirmTitle`/`deleteConfirmDescription` →
  `useDeleteProgramMutation`. Усе клікабельне лежить над кнопкою-назвою: обгортка смітника —
  `relative z-10`, поки підтвердження відкрите (`onOpenChange`) — `z-30`, інакше панель опиняється
  під кнопкою наступної картки; замок `lockSets` (`title`) — `relative z-10`.
- `WorkoutFormPage.tsx` — кнопка «Зберегти як програму»: створює нову
  Програму з поточного стану форми (вправи + кількість підходів кожної, як
  `targetSets`, + сьогоднішня вага > 0 як `extraWeightKg` — бекенд лишає її тільки власній
  вазі); попап із полем назви, підставляється поточна "Назва"
  тренування. Якщо `workout.program` існує — кольоровий бейдж із назвою
  програми біля дати (зникає сам, коли програму видалено, бо `program`
  приходить із бекенду через `workouts.programId`).
- `NewWorkoutButton` об'єднує два джерела шаблонів у одному меню: програми
  показуються першими (авторитетне джерело), історичні `programLabel`-шаблони
  — тільки для міток, які ще не мають збереженої програми (сумісність зі
  старими даними до появи програм).
- Той самий gotcha з транзакцією (`tx.query`, не `db`) стосується і
  `programs.service.ts` (`createProgram`/`updateProgram`).
